# Запуск новой версии: пошаговая инструкция

Инструкция для перехода с работающего **ИТ-инвентаря** на **ИТ-портал** (инвентарь + документы +
задачи с календарём + helpdesk) на сервере Windows **без доступа в интернет**.

Данные инвентаря сохраняются: портал работает с той же базой PostgreSQL и только дополняет её.
Учётные записи и пароли инвентаря продолжают действовать на всём портале.

**Понадобится:**
- компьютер с интернетом — один раз, чтобы скачать проект и его зависимости;
- флешка или общая сетевая папка для переноса файлов;
- доступ к серверу с правами администратора Windows;
- пароль пользователя PostgreSQL, под которым работает инвентарь (он есть в старом файле `.env`);
- 30–60 минут; сам переход (шаги 4–8) занимает около 15 минут, на это время инвентарь будет недоступен.

---

## Шаг 1. Подготовка на компьютере с интернетом

На сервере должен стоять Node.js **18.11 или новее** (проверить: `node -v` в командной строке).
Версия Node.js на компьютере с интернетом значения не имеет — зависимости не компилируются.

1. Скачайте проект: на странице репозитория на GitHub нажмите **Code → Download ZIP** (ветка `main`)
   и распакуйте архив, например в `C:\temp\it-portal`.
   Или: `git clone https://github.com/MaSaHaKa229/it-server.git C:\temp\it-portal`
2. Откройте командную строку в этой папке и установите зависимости:
   ```
   cd C:\temp\it-portal
   npm install --omit=dev
   ```
   Появится папка `node_modules`. Все зависимости — чистый JavaScript, папку можно переносить на другой
   компьютер (в том числе с Linux на Windows и обратно).
3. Собирать что-либо ещё не нужно: интерфейсы «Документов» и «Календаря» уже собраны в `public\docs`
   и `public\calendar`.
4. *(Если планируете nginx — шаг 11.)* Скачайте с nginx.org архив **nginx/Windows** (раздел *Stable version*).
5. Скопируйте на флешку папку `it-portal` **целиком, вместе с `node_modules`** (и архив nginx, если нужен).

> Готовый архив с `node_modules` может также прислать разработчик — тогда этот шаг пропускается.

---

## Шаг 2. Узнайте, как сейчас запущен инвентарь

На сервере найдите папку старого ИТ-инвентаря (в ней лежат `package.json`, папки `server` и `public`)
и выясните, как он запускается — это понадобится на шаге 4:

| Признак | Как запущен |
|---|---|
| Открыто окно командной строки с `IT Inventory запущен: http://localhost:3000` | вручную (`npm start`) |
| `pm2 list` показывает процесс | через pm2 |
| В «Планировщике заданий» есть задание, запускающее `node` или `npm` | через Планировщик |
| В «Службах» (`services.msc`) есть служба для инвентаря | как служба Windows (nssm и т.п.) |

Откройте старый файл `.env` в папке инвентаря (Блокнотом) — его значения понадобятся на шаге 5.

## Шаг 3. Резервная копия базы

Обязательно — это ваша страховка на случай отката.

1. Создайте папку `C:\backup`.
2. В командной строке (путь к PostgreSQL может отличаться — посмотрите номер версии в `C:\Program Files\PostgreSQL\`):
   ```
   "C:\Program Files\PostgreSQL\16\bin\pg_dump.exe" -U itdb -h localhost -Fc -f C:\backup\itdb-before-portal.dump itdb
   ```
   Пароль — значение `PGPASSWORD` из старого `.env`. Имя пользователя и базы тоже берите оттуда
   (`PGUSER`, `PGDATABASE`), если они не `itdb`.
3. Убедитесь, что файл `C:\backup\itdb-before-portal.dump` появился и его размер не нулевой.
4. Скопируйте рядом старый `.env` инвентаря: `copy <папка-инвентаря>\.env C:\backup\inventory.env`

## Шаг 4. Остановите старый инвентарь

В зависимости от того, что выяснили на шаге 2:

- **окно командной строки** — переключитесь в него и нажмите `Ctrl+C`, затем закройте окно;
- **pm2** — `pm2 list`, затем `pm2 stop <имя>` и `pm2 delete <имя>` для процесса инвентаря, затем `pm2 save`;
- **Планировщик заданий** — задание → «Завершить», затем «Отключить»;
- **служба** — `services.msc` → служба → «Остановить», тип запуска «Отключена».

Проверьте, что порт 3000 свободен — команда не должна ничего вывести:
```
netstat -ano | findstr :3000
```

Старую папку инвентаря **не удаляйте** — она нужна для отката.

---

## Шаг 5. Скопируйте портал и настройте `.env`

1. Скопируйте папку `it-portal` с флешки на сервер, например в **`C:\it-portal`**.
2. В папке `C:\it-portal` скопируйте `.env.example` в `.env` и откройте `.env` Блокнотом.
3. Перенесите из старого `.env` инвентаря (`C:\backup\inventory.env`) **точно такие же** значения:

   | Параметр | Зачем |
   |---|---|
   | `SESSION_SECRET` | чтобы не сбросились входы пользователей |
   | **`APP_SECRET_KEY`** | **без него не расшифруются сохранённые пароли устройств** |
   | `PGHOST`, `PGPORT`, `PGUSER`, `PGPASSWORD`, `PGDATABASE` (или `DATABASE_URL`) | подключение к той же базе |

4. Укажите домен внутренней почты, с которой сотрудники смогут регистрироваться на сайте заявок:
   ```
   HELPDESK_EMAIL_DOMAINS=company.local
   ```
   Несколько доменов — через запятую. Позже это можно поменять в интерфейсе.
5. Остальное оставьте как есть. `PORT=3000` — портал, `HELPDESK_PORT=3100` — сайт заявок.
6. Сохраните файл. Убедитесь, что он называется именно `.env`, а не `.env.txt`
   (в Проводнике включите «Вид → Расширения имён файлов»).

---

## Шаг 6. Первый запуск

1. Дважды щёлкните **`C:\it-portal\start-portal.bat`**.
2. В окне должно появиться:
   ```
   Подготовка базы данных…
     ✓ ИТ-инвентарь
     ✓ Портал
     ✓ Документы
     ✓ Задачи и календарь
     ✓ Helpdesk
   ИТ-портал запущен: http://localhost:3000
   Сайт заявок (helpdesk) запущен: http://localhost:3100
   ```
   При первом запуске база дополняется автоматически, повторные запуски ничего не ломают.
3. Если вместо этого ошибка — см. раздел «Если что-то пошло не так» в конце.

Окно пока не закрывайте.

---

## Шаг 7. Проверка

На сервере откройте браузер:

1. `http://localhost:3000` — страница входа. Войдите **прежним логином и паролем суперадмина инвентаря**.
2. Откроется главная страница с плитками: ИТ-инвентарь, Документы, Задачи и календарь, Заявки, Администрирование.
3. Откройте **ИТ-инвентарь**: число единиц техники совпадает с прежним.
4. Откройте любое устройство, у которого были сохранены пароли, и откройте просмотр пароля —
   пароль должен отобразиться. Если ошибка — в `.env` неверный `APP_SECRET_KEY` (шаг 5).
5. `http://localhost:3100` — открывается страница входа и регистрации сайта заявок.

Если всё в порядке — закройте окно `start-portal.bat` (портал остановится) и переходите к шагу 8.

## Шаг 8. Доступ из сети и автозапуск

Откройте **PowerShell от имени администратора** (Пуск → PowerShell → правой кнопкой → «Запуск от имени администратора»):

```
cd C:\it-portal
scripts\firewall.bat
powershell -ExecutionPolicy Bypass -File scripts\install-autostart.ps1
```

- `firewall.bat` открывает в брандмауэре порты 3000 и 3100;
- `install-autostart.ps1` создаёт задание **«IT Portal»** в Планировщике заданий: портал запускается при
  загрузке Windows и перезапускается при сбое. Журнал работы — `C:\it-portal\portal.log`.

Проверьте с другого компьютера сети: `http://<имя-или-IP-сервера>:3000` и `http://<имя-или-IP-сервера>:3100`.

Управление заданием (PowerShell от администратора):
```
Stop-ScheduledTask  -TaskName 'IT Portal'     # остановить
Start-ScheduledTask -TaskName 'IT Portal'     # запустить
```

## Шаг 9. Настройте доступ сотрудников службы ИТ

Войдите на портал администратором → **Администрирование**.

После перехода у прежних пользователей инвентаря:
- редакторы — «Редактирование» в ИТ-инвентаре, читатели — «Просмотр»;
- к Документам, Задачам и Заявкам — **«Нет доступа»**, пока вы его не выдадите.

Для каждого сотрудника ИТ откройте карточку и:
1. Проверьте **ФИО** и укажите **e-mail** — на него приходят уведомления о назначенных заявках (если настроена почта).
2. Выберите уровни доступа к разделам. Кнопки «Быстро задать»: «Сотрудник службы ИТ», «Только просмотр», «Без доступа».
3. Тем, кто будет выполнять заявки, — «Заявки: **Исполнитель**»; тем, кто их распределяет и ставит сроки, — «**Администратор**».
4. При необходимости ограничения: виды документов, «видит только свои задачи». Что именно видит читатель
   инвентаря — настраивается как раньше, в «ИТ-инвентарь → Пользователи».

Новых сотрудников ИТ создавайте там же, кнопкой «Создать пользователя».
Каждый может сменить свой пароль: аватар в правом верхнем углу → «Профиль и пароль».

## Шаг 10. Настройте helpdesk

На портале → **Заявки**, раздел «Настройка» слева:

1. **Регистрация и почта** — проверьте домены почты; при желании включите ручное подтверждение регистраций
   (новый сотрудник ждёт, пока администратор его подтвердит в разделе «Сотрудники»); поправьте приветственный текст.
2. **Виды проблем** — отредактируйте список (принтер, компьютер, программа, сеть…): названия, значки, подсказки,
   исполнитель по умолчанию. Ненужные виды можно скрыть.
3. **Статусы** — при необходимости добавьте свои («Ожидает запчасти» и т.п.); статус по умолчанию получает новая заявка,
   «закрывающие» статусы завершают её.

**Проверка всей цепочки:**
1. На `http://<сервер>:3100` зарегистрируйтесь тестовым сотрудником с рабочей почтой и создайте заявку.
2. На портале → Заявки → откройте её → выберите исполнителя → в появившемся окне задайте срок → «Назначить».
3. Убедитесь, что задача появилась в «Задачах и календаре» у исполнителя (ссылка «Задача в календаре исполнителя» в заявке).
4. На сайте заявок тестовый сотрудник видит исполнителя, срок и статус.
5. Удалите тестовую заявку (кнопка «Удалить» в карточке) и тестового сотрудника (Заявки → Сотрудники → «Изменить» → «Удалить»).

Сообщите сотрудникам предприятия адрес сайта заявок: `http://<имя-сервера>:3100`
(или красивый адрес после шага 11).

## Шаг 10а. Удалённый доступ

1. **Права.** «Администрирование» → у сотрудников ИТ-отдела выберите «Удалённый доступ»: «Управление»
   (или «Только просмотр»); себе — «Администратор» (у администратора портала он есть всегда).
2. **Программа специалиста.** Удалённо: портал → «Удалённый доступ» → «Настройки» → «Установить RemoteSupport» →
   у нужного специалиста «Установить» → компьютер, учётная запись и пароль администратора этого компьютера.
   Требования (брандмауэр, учётная запись) — по ссылке «Что нужно на компьютере специалиста» там же.
   Вручную: «Установка» → скачайте `ITRemoteViewer.exe` (Windows 10/11) или `ITRemoteViewer-win7.exe` (Windows 7/8.1),
   запустите, нажмите «Открывать ссылки из портала этой программой».
3. **Агент на компьютере пользователя.** Там же, на вкладке «Установка», — готовая команда с кодом регистрации.
   Сначала поставьте агент на 1–2 тестовых компьютера. Для всех компьютеров — файл массовой установки
   (запуск от имени администратора или сценарий запуска компьютера в групповой политике).
4. **Проверка.** Компьютер появился на вкладке «Компьютеры» со статусом «в сети» и привязался к технике.
   Откройте карточку этой техники → «Подключиться» → программа открывается, у пользователя — вопрос
   «Разрешить подключение?», после ответа «Да» — плашка «Подключён специалист». Запись — в «Журнале».
5. Агенты открывают у себя в брандмауэре Windows порт **TCP 5960**. Если между отделами есть другие
   брандмауэры — разрешите этот порт от компьютеров ИТ-отдела. На сервере портала новых портов открывать не нужно.

## Шаг 11 (по желанию). Отдельные адреса через nginx

Чтобы портал открывался как `http://it.company.local`, а сайт заявок — как `http://helpdesk.company.local`:

1. **Имена в сети.** В «Диспетчере DNS» (если есть домен Active Directory) создайте в зоне `company.local`
   A-записи `it` и `helpdesk` на IP сервера. Без DNS-сервера — добавьте на каждом компьютере в
   `C:\Windows\System32\drivers\etc\hosts`:
   ```
   192.168.1.10  it.company.local
   192.168.1.10  helpdesk.company.local
   ```
2. **nginx.** Распакуйте архив nginx в `C:\nginx`. Скопируйте `C:\it-portal\scripts\nginx.conf`
   в `C:\nginx\conf\nginx.conf` и замените в нём `it.company.local` / `helpdesk.company.local` на свои имена.
3. **`.env` портала** — добавьте (или раскомментируйте) и перезапустите задание «IT Portal»:
   ```
   TRUST_PROXY=1
   PORTAL_URL=http://it.company.local
   HELPDESK_URL=http://helpdesk.company.local
   ```
4. **Автозапуск nginx** (PowerShell от администратора):
   ```
   cd C:\it-portal
   powershell -ExecutionPolicy Bypass -File scripts\install-nginx-autostart.ps1 -ClosePortalPorts
   ```
   Ключ `-ClosePortalPorts` закрывает из сети прямой доступ к портам 3000 и 3100 — заходить можно будет
   только по новым адресам. На время перехода его можно не указывать.
5. Проверьте с другого компьютера: `http://it.company.local` и `http://helpdesk.company.local`.

Подробности и HTTPS — в README, раздел «Свои адреса для портала и сайта заявок (nginx)».

## Шаг 12 (по желанию). Почта

Если есть внутренний почтовый сервер, допишите в `.env` и перезапустите задание «IT Portal»:
```
SMTP_HOST=mail.company.local
SMTP_PORT=25
SMTP_USER=helpdesk@company.local
SMTP_PASS=пароль
MAIL_FROM=Служба ИТ <helpdesk@company.local>
```
После этого:
- сотрудники подтверждают регистрацию кодом из письма и сами восстанавливают забытый пароль;
- заявитель получает письма о приёме заявки, смене статуса и ответах ИТ;
- исполнитель — о назначении заявки, администраторы helpdesk — о новых заявках.

Без почты всё работает, просто без писем: забытый пароль сотруднику сбрасывает администратор
(Заявки → Сотрудники → «Изменить» → новый пароль).

## Шаг 13. Регулярные резервные копии

Одна база — одна копия для всех разделов. Пример файла `C:\backup\backup.bat`:
```
@echo off
set PGPASSWORD=пароль_itdb
"C:\Program Files\PostgreSQL\16\bin\pg_dump.exe" -U itdb -h localhost -Fc -f "C:\backup\itdb-%date:~6,4%-%date:~3,2%-%date:~0,2%.dump" itdb
forfiles /p C:\backup /m itdb-*.dump /d -30 /c "cmd /c del @path"
```
Добавьте его в Планировщик заданий (ежедневно, ночью). Последняя строка удаляет копии старше 30 дней.
Имя файла собирается из даты в формате `ДД.ММ.ГГГГ` (русская региональная настройка Windows).
Значение `APP_SECRET_KEY` из `.env` храните отдельно в надёжном месте — без него пароли устройств из копии не расшифровать.

## Если что-то пошло не так

| Сообщение / симптом | Что сделать |
|---|---|
| `Заполните SESSION_SECRET и APP_SECRET_KEY` | Нет файла `.env` в `C:\it-portal` или он называется `.env.txt` (шаг 5) |
| `ECONNREFUSED 127.0.0.1:5432` | Не запущена служба PostgreSQL: `services.msc` → `postgresql-x64-…` → «Запустить» |
| `password authentication failed` | Неверные `PGUSER` / `PGPASSWORD` в `.env` — сверьте со старым `.env` |
| `Не удалось установить расширение pg_trgm` | Один раз выполните от пользователя `postgres` в базе инвентаря (pgAdmin → база → Query Tool): `CREATE EXTENSION IF NOT EXISTS pg_trgm WITH SCHEMA public;` |
| `EADDRINUSE` / порт занят | Не остановлен старый инвентарь (шаг 4) или уже запущено задание «IT Portal» |
| `Cannot find module …` | Не скопирована папка `node_modules` (шаг 1) |
| Пароли устройств не показываются | В `.env` не тот `APP_SECRET_KEY` — перенесите из старого `.env` и перезапустите |
| С других компьютеров не открывается | Брандмауэр (шаг 8), IP/имя сервера, для nginx — DNS/hosts (шаг 11) |
| Ошибки при работе | Смотрите `C:\it-portal\portal.log` |

### Откат на старый инвентарь

1. Остановите и отключите портал: `Stop-ScheduledTask -TaskName 'IT Portal'`, затем
   `Disable-ScheduledTask -TaskName 'IT Portal'` (и задание `nginx`, если создавали).
2. Восстановите базу из копии шага 3:
   ```
   "C:\Program Files\PostgreSQL\16\bin\pg_restore.exe" -U itdb -h localhost -d itdb --clean --if-exists C:\backup\itdb-before-portal.dump
   ```
3. Запустите старый инвентарь так же, как он работал раньше (шаг 2), и включите обратно его автозапуск.

> Откат по копии вернёт базу на момент шага 3: всё, что внесли в портал после этого (документы, задачи, заявки,
> изменения техники), будет потеряно.

## Обновление до следующих версий

1. На компьютере с интернетом скачайте новую версию и выполните `npm install --omit=dev` (как в шаге 1).
2. Сделайте резервную копию базы (шаг 3).
3. Остановите портал: `Stop-ScheduledTask -TaskName 'IT Portal'`.
4. В `C:\it-portal` замените папки `server`, `public`, `scripts`, `node_modules` и файлы `package.json`,
   `package-lock.json`, `start-portal.bat`. **Файл `.env` не трогайте.**
