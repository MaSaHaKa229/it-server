# ИТ-портал

Единый сайт ИТ-отдела на **Node.js + PostgreSQL**, объединяющий три приложения
и новый сервис заявок:

| Адрес | Что это | Для кого |
|---|---|---|
| `http://сервер:3000/` | **Главная страница** — плитки разделов, сводка | ИТ-отдел |
| `http://сервер:3000/inventory/` | **ИТ-инвентарь** (бывший it-inventory, все данные сохраняются) | ИТ-отдел |
| `http://сервер:3000/docs/` | **Документы** (бывший docsearch) | ИТ-отдел |
| `http://сервер:3000/calendar/` | **Задачи и календарь** (бывший dept-calendar) | ИТ-отдел |
| `http://сервер:3000/helpdesk/` | **Заявки** — обработка заявок: исполнители, сроки, статусы | ИТ-отдел |
| `http://сервер:3000/admin` | **Администрирование** — пользователи и права | администраторы |
| `http://сервер:3100/` | **Сайт заявок** — регистрация по рабочей почте, подача заявок | все сотрудники предприятия |

Оба порта обслуживает один процесс Node.js (`npm start` или `start-portal.bat`).
Всё работает без интернета: внешних скриптов, шрифтов и CDN нет.

## Вход и права доступа

- **Один логин на все разделы.** Учётные записи — это пользователи ИТ-инвентаря: после
  обновления все прежние логины и пароли продолжают работать. Войти можно по логину или e-mail.
- **Администратор портала** (роль «суперадмин» из инвентаря) видит всё и в разделе
  «Администрирование» решает, что доступно каждому сотруднику:

| Раздел | Уровни доступа | Дополнительные ограничения |
|---|---|---|
| ИТ-инвентарь | нет / просмотр / редактирование | для просмотра — типы техники, отделы, видимые поля, ПО, пароли, выгрузка в Excel (настраивается в «ИТ-инвентарь → Пользователи», как и раньше) |
| Документы | нет / просмотр / редактирование | доступные виды документов (законы, ГОСТы, указы, регламенты, прочее) |
| Задачи и календарь | нет / просмотр / редактирование / администратор | «видит только свои задачи» |
| Заявки (Helpdesk) | нет / исполнитель / администратор | — |

- Кнопки «Быстро задать» в карточке пользователя: «Сотрудник ИТ-отдела», «Только просмотр», «Без доступа».
- Права проверяются на сервере при каждом запросе; отключение пользователя сразу завершает его сессию.
- Прежние пользователи инвентаря после обновления получают: редакторы — «редактирование» инвентаря,
  читатели — «просмотр»; к документам, календарю и заявкам — «нет доступа», пока администратор его не выдаст.

## Helpdesk

**Сотрудники предприятия** (сайт на порту 3100):
- регистрируются сами по **внутренней почте** — принимаются только адреса разрешённых доменов
  (`HELPDESK_EMAIL_DOMAINS` в `.env` или «Заявки → Регистрация и почта»);
- при настроенном SMTP подтверждают адрес кодом из письма и могут сами восстановить пароль;
  без SMTP можно включить ручное подтверждение регистраций администратором;
- создают заявку: вид проблемы (принтер, компьютер, программа, сеть…), тема, описание, кабинет,
  срочность, до 5 файлов (фото, скриншоты);
- видят **свои заявки**: статус и ход выполнения, исполнителя, срок, историю изменений,
  переписку с ИТ-отделом; могут дописать уточнение и приложить файлы.

**ИТ-отдел** (раздел «Заявки» портала):
- *Исполнитель* видит все заявки, берёт свободные в работу, меняет статус и приоритет своих,
  отвечает заявителю или пишет внутренние заметки (заявитель их не видит), привязывает технику из инвентаря.
- *Администратор helpdesk* дополнительно:
  - **назначает исполнителей** и при назначении сразу **выставляет срок** (быстрые кнопки «сегодня 18:00», «завтра», «+3 дня»…);
    срок меняет только администратор — заявитель указывает лишь срочность (приоритет), исполнитель срок не меняет;
  - добавляет и изменяет **виды поломок** (значок, описание, исполнитель по умолчанию);
  - добавляет **статусы** (цвет, порядок, статус для новых заявок, «закрывающие» статусы);
  - видит **зарегистрированных сотрудников**: отдел, контакты, число заявок; подтверждает
    регистрации, блокирует, сбрасывает пароль;
  - настраивает домены почты и ручное подтверждение регистраций.
- Фильтры: мои, без исполнителя, просроченные, закрытые; по статусу, виду, исполнителю, приоритету; поиск.
- Сводка по заявкам — на главной странице портала.

**Заявки в календаре.** Заявка с исполнителем автоматически становится задачей в разделе
«Задачи и календарь» (категория «Заявки», название «#номер тема», исполнитель тот же):
- со сроком — задача стоит в календаре за час до срока, без срока — на весь день назначения;
- смена исполнителя, срока, приоритета, статуса в заявке сразу меняет задачу; закрытие заявки
  делает задачу «Выполнена» (статусы со словами «отклонена/отменена» — «Отменена»);
- исполнителя сняли или заявку удалили — задача удаляется;
- синхронизация односторонняя: срок и статус заявки меняются только в helpdesk, правки задачи в календаре
  при следующем изменении заявки перезаписываются (кроме дня задачи без срока — её можно переставить);
- в карточке заявки — ссылка «Задача в календаре исполнителя», в задаче — «Открыть заявку»;
- уже назначенные открытые заявки попадают в календарь при запуске новой версии.

Уведомления по почте (если указан SMTP): заявителю — о смене статуса и ответах; исполнителю — о назначении
и комментариях заявителя; администраторам helpdesk — о новых заявках и регистрациях.
E-mail сотрудника ИТ берётся из его профиля портала.

## Обновление работающего ИТ-инвентаря (Windows, без интернета)

Портал использует **ту же базу PostgreSQL**, что и ИТ-инвентарь. Таблицы инвентаря не меняются
(добавляется только колонка `users.modules`), остальные модули создают свои схемы `docs`, `calendar`, `helpdesk`.

1. **Подготовка (на компьютере с интернетом)** — нужна папка проекта вместе с `node_modules`:
   ```
   npm install --omit=dev
   ```
   Все зависимости — чистый JavaScript, папку можно переносить между Windows и Linux.
   Фронтенды «Документов» и «Календаря» уже собраны (`public/docs`, `public/calendar`), собирать их не нужно.

2. **Резервная копия базы** на сервере (в «Командной строке»):
   ```
   "C:\Program Files\PostgreSQL\16\bin\pg_dump.exe" -U itdb -h localhost -Fc -f C:\backup\itdb-before-portal.dump itdb
   ```

3. **Остановите старый ИТ-инвентарь** (окно с `npm start`, задание Планировщика, pm2 — как он у вас запущен).

4. **Скопируйте папку портала** на сервер, например в `C:\it-portal`, и создайте `.env`:
   скопируйте `.env.example` в `.env` и перенесите из старого `.env` инвентаря значения
   `SESSION_SECRET`, **`APP_SECRET_KEY`** (без него не расшифруются пароли устройств) и параметры
   подключения `PGHOST`, `PGUSER`, `PGPASSWORD`, `PGDATABASE`. Укажите домен почты в `HELPDESK_EMAIL_DOMAINS`.

5. **Запустите** `start-portal.bat` (или `npm start`). При первом запуске база дополняется автоматически.
   Откройте `http://localhost:3000` и войдите прежним логином суперадмина инвентаря.

6. **Сеть и автозапуск** (PowerShell / командная строка от имени администратора):
   ```
   scripts\firewall.bat
   powershell -ExecutionPolicy Bypass -File scripts\install-autostart.ps1
   ```
   Первый скрипт открывает порты 3000 и 3100, второй создаёт задание «IT Portal» в Планировщике заданий
   (запуск при загрузке Windows, перезапуск при сбое, журнал — `portal.log`).

7. **Настройте доступ**: «Администрирование» → карточка каждого сотрудника ИТ → разделы и уровни.
   В «Заявки → Виды проблем / Статусы» поправьте справочники под себя, сообщите сотрудникам адрес
   `http://<имя-сервера>:3100`.

Старые закладки вида `http://сервер:3000/#/devices/5` автоматически открываются в `/inventory/`.

### Если что-то пошло не так

| Сообщение | Что сделать |
|---|---|
| `Не удалось установить расширение pg_trgm` | Один раз выполнить от имени `postgres` в базе itdb: `CREATE EXTENSION IF NOT EXISTS pg_trgm WITH SCHEMA public;` |
| `Заполните SESSION_SECRET и APP_SECRET_KEY` | Нет файла `.env` рядом с `package.json` |
| `ECONNREFUSED 127.0.0.1:5432` | Не запущена служба PostgreSQL («Службы» → `postgresql-x64-…`) |
| Порт занят (`EADDRINUSE`) | Не остановлен старый инвентарь, либо поменяйте `PORT` / `HELPDESK_PORT` в `.env` |
| Вернуть всё как было | Остановить портал, восстановить копию: `pg_restore -U itdb -h localhost -d itdb --clean C:\backup\itdb-before-portal.dump`, запустить старый инвентарь |

## Свои адреса для портала и сайта заявок (nginx)

Чтобы сотрудники открывали не `http://сервер:3100`, а понятные адреса, перед порталом ставится nginx:

- `http://it.company.local` → ИТ-портал (`127.0.0.1:3000`)
- `http://helpdesk.company.local` → сайт заявок (`127.0.0.1:3100`)
- обращение по IP сервера → перенаправление на сайт заявок

Имена условные — замените на свои во всех шагах.

1. **Имена в сети.** Если есть Active Directory / DNS-сервер: в «Диспетчере DNS» в зоне `company.local`
   создайте A-записи `it` и `helpdesk` на IP сервера портала. Без DNS-сервера — строки в
   `C:\Windows\System32\drivers\etc\hosts` на каждом компьютере:
   ```
   192.168.1.10  it.company.local
   192.168.1.10  helpdesk.company.local
   ```
2. **nginx.** На компьютере с интернетом скачайте с nginx.org архив *nginx/Windows* (stable), перенесите на сервер,
   распакуйте в `C:\nginx`. Скопируйте `scripts\nginx.conf` в `C:\nginx\conf\nginx.conf` и замените в нём имена.
3. **`.env` портала** — раскомментируйте и заполните, затем перезапустите портал:
   ```
   TRUST_PROXY=1
   PORTAL_URL=http://it.company.local
   HELPDESK_URL=http://helpdesk.company.local
   ```
   `TRUST_PROXY=1` нужен, чтобы портал видел настоящий IP пользователя (защита от перебора паролей),
   адреса — для ссылок на главной странице, странице входа и в письмах.
4. **Автозапуск и брандмауэр** (PowerShell от имени администратора):
   ```
   powershell -ExecutionPolicy Bypass -File scripts\install-nginx-autostart.ps1 -ClosePortalPorts
   ```
   Скрипт проверяет конфигурацию, создаёт задание «nginx» в Планировщике заданий, открывает порт 80,
   а с `-ClosePortalPorts` закрывает из сети прямой доступ к портам 3000 и 3100 (портал доступен только через nginx).
   Без ключа порты остаются открытыми — удобно на время перехода.

После изменения `nginx.conf`: `cd C:\nginx` → `nginx -t` → `nginx -s reload`.

| Проблема | Что проверить |
|---|---|
| Адрес не открывается | `ping it.company.local` должен отвечать IP сервера (DNS / hosts) |
| 502 Bad Gateway | Не запущен портал (задание «IT Portal», `portal.log`) |
| 413 Request Entity Too Large | Увеличить `client_max_body_size` в `nginx.conf` |
| Открывается не тот сайт | Имя в адресе не совпадает с `server_name` в `nginx.conf` |

**HTTPS** (по желанию): выпустите сертификат на оба имени во внутреннем центре сертификации (например, AD CS),
раскомментируйте блоки `listen 443 ssl` в конце `scripts\nginx.conf`, в блоках на порту 80 замените `proxy_pass`
на `return 301 https://$host$request_uri;`, в `.env` укажите `COOKIE_SECURE=true` и адреса с `https://`.

## Новая установка (без существующего инвентаря)

Нужны Node.js 18.11+ и PostgreSQL 13+.

```
CREATE USER itdb WITH PASSWORD 'itdb_password';
CREATE DATABASE itdb OWNER itdb;
```
```
npm install --omit=dev
copy .env.example .env      (заполните SESSION_SECRET, APP_SECRET_KEY)
npm run init-db             (или npm run demo — с примерами техники)
npm start
```
Вход: `admin` / `admin12345` (задаётся в `.env`) — смените пароль в меню профиля.

## Резервное копирование

Одна база — одна копия для всех разделов:
```
pg_dump -U itdb -h localhost -Fc -f itdb.dump itdb
```
Храните вместе с копией значение `APP_SECRET_KEY`.

## Структура

```
server/
  index.js            запуск: портал (PORT) и сайт заявок (HELPDESK_PORT)
  setup.js            подготовка БД всех модулей (идемпотентно, при каждом запуске)
  db.js               подключение к PostgreSQL, пулы по схемам
  portal/             вход, профиль, права на модули, администрирование, синхронизация пользователей
  inventory/          ИТ-инвентарь (схема public)
  docs/               реестр документов (схема docs)
  calendar/           задачи и календарь (схема calendar, ES-модули)
  helpdesk/           заявки (схема helpdesk): сайт сотрудников, API ИТ-отдела, уведомления
public/
  portal/             главная, вход, администрирование
  inventory/          интерфейс инвентаря
  docs/, calendar/    собранные React-приложения (из clients/)
  helpdesk-staff/     рабочее место ИТ-отдела по заявкам
  helpdesk/           сайт заявок для сотрудников
  shared/             общие стили и компоненты
clients/docs, clients/calendar   исходники React-приложений (Vite)
scripts/              брандмауэр, автозапуск портала и nginx для Windows, nginx.conf
```

Пользователи портала (`public.users`) копируются в `docs.users` и `calendar.users` с теми же id —
так работают связи «автор документа», «исполнитель задачи». Править их нужно только через «Администрирование».

## Разработка

```
npm install
npm run dev                  # сервер с перезапуском при изменениях
npm run build:install        # зависимости React-клиентов (нужен интернет)
npm run build                # пересобрать public/docs и public/calendar
```
